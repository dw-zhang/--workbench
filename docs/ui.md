# 两个界面：管理员 / 员工

> 同一套页面、同一个端口，**不是两个系统**。区别只有三点：从哪个入口登录、侧边栏露出多少、看到的是谁的数据。
> 本文按真实界面逐块说明，配合 [install.md](install.md) 走完首次配置；凭证字段级说明见 [config.md](config.md)。

---

## 0. 一图看懂

```
                         http://SERVER_IP:8787
                                  │
                    ┌─────────────┴──────────────┐
                    │        登录卡（全屏）        │
                    │  ┌──────────┬───────────┐  │
                    │  │ 用钉钉身份进入 │ 管理员 │  │
                    │  └──────────┴───────────┘  │
                    └───────┬───────────┬────────┘
              钉钉客户端内自动免登 │           │ 输入管理员密码（.env 里 WB_ADMIN_PASS）
              浏览器里扫码登录   │           │
                    ┌───────▼───────┐   ┌────▼─────────────┐
                    │   员工界面     │   │   管理员界面      │
                    │ 只看自己的数据  │   │ 全量数据 + 控制台  │
                    │ 无配置入口     │   │ 人员/凭证/自检     │
                    └───────────────┘   └──────────────────┘
```

- **员工界面**：钉钉身份进入，服务端按 `person_id` 强制过滤，侧边栏没有任何"配置"入口。
- **管理员界面**：密码进入，可看全量、可改凭证、可拉人员；顶栏胶囊变成 `🛡 名字`。

两边是同一套页面文件（`static/index.html` + `static/auth-ui.js`），差别由登录态决定，**没有被隐藏的"另一个网址"**。

## 1. 登录卡长什么样

未登录时整页被一张卡盖住（其余内容不渲染数据，避免闪一下再消失）：

```
┌─────────────────────────────────────────────┐
│  任务安排工作台                                │
│  用钉钉身份进入 · 只在钉钉里才能免登            │
│  ┌──────────────┬────────────┐              │
│  │ 用钉钉身份进入 │   管理员    │  ← 两个 tab   │
│  └──────────────┴────────────┘              │
│                                             │
│  （默认 tab）钉钉内：正在识别你的钉钉身份…      │
│  普通浏览器：钉钉扫码登录  →  跳到扫码页        │
│                                             │
│  （管理员 tab）请输入管理密码                   │
│  [ ********** ]   [ 登录 ]                   │
│                                             │
│  钉钉免登失败时会给具体原因，例如：             │
│  · JSAPI 4040：当前页面不在钉钉客户端内        │
│  · dd.config 校验失败（签名不匹配）：首页地址   │
│    与访问地址不一致，必须含端口、不能带路径      │
└─────────────────────────────────────────────┘
```

| 场景 | 会发生什么 |
|---|---|
| 钉钉客户端 → 工作台 → 点开本应用 | 自动免登，直接进员工界面，无需输密码 |
| 电脑浏览器打开 | 提示不在钉钉容器内（4040），自动改用「钉钉扫码登录」 |
| 要配置系统 | 切到「管理员」tab，输 `.env` 的 `WB_ADMIN_PASS` |
| 钉钉应用还没配好凭证 | 管理员 tab 仍可登录（密码存在本地库），先把凭证填进去 |

> 管理员密码首次启动时写入数据库（PBKDF2 哈希），之后**改 `.env` 不再生效**，用控制台「修改密码」改。

## 2. 员工界面

### 2.1 骨架

```
┌────────────┬──────────────────────────────────────────────────┐
│ 📋 我的工作台│  [🔍 问 AI：今天有什么安排 / 新建任务 …]  👤 张三  退出 │
│            ├──────────────────────────────────────────────────┤
│ 工作区      │  任务安排工作台                                     │
│ 🏠 首页     │  ┌────────┬────────┬────────┬────────┐            │
│ ✅ 任务管理  │  │今日待办 │本周重点 │等待回复 │已完成  │  ← 点卡片直达 │
│ 📊 数据看板  │  └────────┴────────┴────────┴────────┘   ┌──────┐│
│ 🗓 日程看板  │  今日日程 / 即将到期 / 最近资料 / 待我审批 │ 日历 ││
│ 📅 日历     │                                          └──────┘│
│ 🎥 会议     │                                                   │
│ 协作        │                                                   │
│ 💬 等待回复 ③│                                                  │
│ 📁 资料整理  │                                                  │
│ 管理        │                                                   │
│ 🤖 AI 助手  │                                                   │
│ 应用中心     │                                                   │
│ 📌 钉钉审批  │                                                   │
└────────────┴──────────────────────────────────────────────────┘
```

员工侧边栏**没有**「分类 / 设置 / 应用接入」——这三个入口会被物理隐藏，直接手输 `#/settings`、`#/apps`、`#/categories` 也会被弹回首页。

### 2.2 员工能做什么

| 页面 | 员工看到的内容 |
|---|---|
| 🏠 首页 | 只有自己的待办、日程、等待回复、待我审批、最近资料 |
| ✅ 任务管理 | 自己的任务（钉钉待办 / GitHub Issue / 手工建的），可改状态、标完成 |
| 📊 数据看板 | 自己的审批金额、任务量、消息量统计 |
| 🗓 日程看板 / 📅 日历 / 🎥 会议 | 自己的日程与会议（会议按参与/组织关系过滤） |
| 💬 等待回复 | 群消息里 @自己 的、待自己回的；可标「已回复」 |
| 📁 资料整理 | 只有自己在钉钉里有权限的知识库/文档（同步时用本人身份枚举，没权限的根本不入库） |
| 🤖 AI 助手 | 对话 + 17 个工具，全部按本人数据回答；底部可配自己的 AI 模型 |
| 📌 钉钉审批 | 首页审批区，可点「AI 判断」看建议（只出建议，不代批） |

### 2.3 顶栏身份区

```
👤 张三   退出      ← 员工
🛡 张三   退出      ← 管理员（前缀不同）
```

点头衔胶囊：员工看到的是「当前身份」面板，只有一句说明 + 「退出登录」；
管理员点同一个胶囊，看到的是**管理员控制台**。这就是两个界面唯一的"开关"。

### 2.4 员工看不到数据时的提示（不是空白页）

员工刚登录、或管理员还没给他人/他绑账号时，页面顶部会出现一条黄色提示条，直接说原因：

| 提示 | 含义 | 谁去修 |
|---|---|---|
| 你的账号没有匹配到任何待办 / 审批 | 系统里已有数据，但这个钉钉账号没绑到人员 | 管理员 → 人员管理 → 核对手机号/邮箱 |
| 钉钉「OA 审批」权限未开通 | 应用缺 `qyapi_work_record`，审批一条都进不来 | 管理员 → 平台配置/去开通权限 |
| 人员库里还没有可同步的成员 | 还没拉通讯录 | 管理员 → 人员管理 → 拉取钉钉通讯录 |
| 工作台还没有任何数据 | 从没成功同步过 | 管理员点「立即同步」 |

> 「立即同步」按钮只有管理员可见（在右下角悬浮的同步状态卡里），员工页面上出现的提示条不会带同步按钮。

## 3. 管理员界面

### 3.1 怎么进

```
① 浏览器打开 http://SERVER_IP:8787
② 登录卡 → 切到「管理员」tab → 输入 WB_ADMIN_PASS → 登录
③ 顶栏出现 🛡 名字 → 点它 → 弹出「管理员控制台」
```

管理员进入后**页面本身和员工一样**（同样的侧边栏、同样的 8 个页面），
额外多了三件东西：

1. 侧边栏完整露出「分类 / 设置 / 应用接入」；
2. 右下角多一张**同步状态卡**：

```
                              ┌──────────────────────────────────────┐
                              │ ● 已连接 · 最后同步 2026-11-15 18:02   │
                              │   [立即同步]  [连接设置]              │
                              └──────────────────────────────────────┘
```

   状态点：灰=未检查、绿=已连接、黄=未配置/还没同步过、蓝=同步中。
   `连接设置` 直接跳 `#/settings` 的接入状态；`立即同步` 触发一轮按人同步。

3. 点顶栏胶囊 → 管理员控制台（配置都在这里）。

### 3.2 管理员控制台

一个居中的大弹层，右上角「关闭」，顶部一排功能按钮：

```
┌──────────────────────────────────────────────────────────────┐
│ 管理员控制台                                           [关闭] │
│ 人员绑定、平台凭证都在这里；员工页面看不到这些入口。              │
│ ┌────────┬────────┬────────────┬────────┬──────────┐        │
│ │人员管理 │平台配置 │钉钉免登自检 │修改密码 │ 退出登录  │        │
│ └────────┴────────┴────────────┴────────┴──────────┘        │
│                                                              │
│ （默认打开「人员管理」）                                        │
│ ┌拉取钉钉通讯录┬拉取飞书通讯录┬拉取金蝶用户┬拉取禅道用户┬…┐        │
│ │重新自动匹配 │手动加人                                  │        │
│ └──────────────────────────────────────────────────────┘    │
│ 共 128 人 · 已绑定 96 · 冲突 3 · 未匹配 29 ｜ 平台账号：…       │
│ ┌────┬──────────────────┬──────────┬──────┬──────┬────────┐ │
│ │姓名 │平台账号（徽标）     │手机      │邮箱   │状态  │操作     │ │
│ │张三 │dingtalk:0123 ✅   │138****  │—     │已绑定│绑账号 删除│ │
│ │李四 │dingtalk —  feishu —│139**** │—     │未匹配│绑账号 删除│ │
│ └────┴──────────────────┴──────────┴──────┴──────┴────────┘ │
└──────────────────────────────────────────────────────────────┘
```

#### ① 人员管理

- 拉取按钮：钉钉 / 飞书 / 金蝶 / 禅道 / GitLab / Gitea 通讯录（拉谁取决于对应平台凭证是否已配）
- `重新自动匹配`：手机号或邮箱任一命中即绑定；多人命中同一账号 → 标「冲突」等人工裁决
- `手动加人`：无通讯录权限时手工建人
- 表格列：姓名 / 平台账号徽标（`dingtalk:xxx`、`feishu:xxx`…，未绑定显示 `—`）/ 手机 / 邮箱 / 状态（已绑定·冲突·未匹配·手动·已停用）/ 操作（绑账号、删除）
- 绑定语义：**一个 person 可以挂多个平台账号**，工作台把各平台的待办/审批归并到同一个人

#### ② 平台配置

九个平台各一张卡片，卡片标题右侧有「已配置 / 未配置」徽标，每个字段一行，改完点该卡片的「保存」立即生效（不用重启）：

| 卡片 | 需要填的字段 |
|---|---|
| 钉钉 | AppKey / AppSecret / CorpId / AgentId / 对外访问地址 / 管理员钉钉 UserID，以及 7 个开关项（单点即管理员、只收@我、各类通知开关、审批模板编码、抄送核对条数/天数、免打扰时段） |
| 飞书 | App ID / App Secret |
| GitHub | Personal Access Token / 仓库（owner/repo，逗号分隔）/ 组织 / Webhook 密钥 |
| GitLab | GitLab 地址 / Access Token / 组路径 |
| Gitea/Gogs | 地址 / Access Token / 组织 |
| 禅道 | 地址 / API 账号 / 密码 |
| 金蝶云星空 | 星空地址 / 账套ID / 应用ID / 应用密钥 / 接口用户 |
| 用友 | 开放平台地址 / AppKey / AppSecret / 企业编码 / 接口用户编码 / 待办接口路径 |
| 企业微信 | CorpID / 应用 Secret / AgentId |

Secret 类字段（AppSecret、Token、密码、密钥）**永不回传浏览器**：已保存过的字段显示占位符「已保存（留空不修改）」，想改就重新输一遍。

#### ③ 钉钉免登自检

点开自动跑一遍，输出一张四列表：

| 检查项 | 结果 | 实际值 | 修复建议 |
|---|---|---|---|
| 凭证（AppKey/AppSecret/CorpId） | 正常/异常 | 齐全 / 缺少哪几项 | 平台配置 → 钉钉 补齐 |
| AgentId（微应用ID） | 正常/异常 | 已填的值 / 未填 | 开放平台 → 应用 → 凭证与基础信息 → AgentId |
| 扫码登录回调地址 | 正常 | 自动拼出的 `/auth/dingtalk/callback` | 到开放平台「登录与分享 → 回调域名」填这个域名 |
| 获取 access_token | 正常/异常 | 成功（凭证有效、应用已发布）/ 钉钉的 errmsg | 检查 Secret 是否完整、应用是否发布、服务器出口 IP 是否在白名单 |
| 获取 jsapi_ticket | 正常/异常 | 成功 / 报错 | 开通「JSAPI 鉴权」后重新发布 |
| 权限（逐项） | 正常/异常 | 具体权限名 | 按提示点链接申请，再发布版本 |

底部固定提示：还有两项在钉钉后台、程序查不到——① 应用「首页地址」② 权限管理里已开通「JSAPI 鉴权 / 成员信息读」并已发布版本。

#### ④ 修改密码

原密码 + 新密码（≥6 位）→ 保存 → 会话失效，用新密码重新登录。

### 3.3 管理员看到的额外内容

| 位置 | 管理员才有的 |
|---|---|
| 右下角 | 同步状态卡（状态点 + 立即同步 + 连接设置），员工被 CSS 强制隐藏 |
| 侧边栏 | 分类 / 设置 / 应用接入 |
| 数据范围 | 不带 `?person=` 时看全量；可用 `?person=<id>` 精确看某个人 |

| 应用接入页 | 新增/编辑接入记录（含 `应用类型=AI 接口`） |

## 5. API / 凭证到底在哪填（四个入口，别混）

这是问得最多的一个问题。**代码里没有任何密钥**，所有凭证都在网页里填，共四个入口：

```
填钉钉    ┬─ 管理员控制台 → 平台配置 → 钉钉卡片（字段最全：含 AgentId + 7 个开关）
          ├─ 设置页底部「钉钉连接」卡（4 个字段 + 自动同步间隔 + 测试连接/立即同步）
          └─ 应用接入页 —— 只登记"接入状态"，不是凭证主入口
填 AI     ┬─ AI 助手页(#/ai) → 我的 AI 模型      ← 个人，员工也能用
          └─ config 表 ai:global                ← 全局，全公司共用
填运行参数 ── .env / 环境变量（端口、管理员密码、数据路径、演示数据）
```

### 5.1 钉钉（必填）→ 两处等价入口

**推荐：管理员控制台 → 平台配置 → 钉钉卡片**，字段最全：

| 字段 | 说明 | 从哪拿（钉钉开放平台 → 应用开发 → 企业内部应用 → 你的应用） |
|---|---|---|
| AppKey | 应用凭证 | 「凭证与基础信息」 |
| AppSecret | 应用密钥（只存服务端，不回显） | 同页下方 |
| CorpId | 企业 ID | 「企业信息」，或开发者后台首页 |
| AgentId | 微应用 ID（免登 / 工作通知要用） | 「版本管理与发布 / 基础信息」 |
| 对外访问地址 | 你实际访问的地址，如 `http://192.168.1.10:8787` | 自己服务器地址（扫码回调按它拼，**含端口、不带路径**） |
| 管理员钉钉 UserID | 可选，填了才能「钉钉单点登录即管理员」 | 管理后台 → 通讯录 → 成员 → 账号信息 userid |
| 其余 7 项开关 | 单点即管理员、只收 @我、各类通知开关、审批模板编码、抄送核对条数/天数、免打扰时段 | 按需，留空即默认 |

**另一条路：设置页（#/settings）底部的「钉钉连接」卡**（只有管理员能看到），
字段是 AppKey / AppSecret / 企业 CorpId / 同步谁的数据(UserID) 四个，加「自动同步间隔」「开启自动同步」，
按钮 `保存配置` / `测试连接` / `立即同步`，下方是最近 8 条同步记录。

> 两处写的是同一份配置（`config` 表 `dingtalk:*`），在哪填都一样；AgentId 等字段只在前者能改。

### 5.2 其它业务平台 → 管理员控制台 → 平台配置

| 卡片 | 需要填的字段 |
|---|---|
| 飞书 | App ID / App Secret |
| GitHub | Personal Access Token / 仓库（owner/repo，逗号分隔）/ 组织 / Webhook 密钥 |
| GitLab | GitLab 地址 / Access Token / 组路径 |
| Gitea/Gogs | 地址 / Access Token / 组织 |
| 禅道 | 地址 / API 账号 / 密码 |
| 金蝶云星空 | 星空地址 / 账套ID / 应用ID / 应用密钥 / 接口用户 |
| 用友 | 开放平台地址 / AppKey / AppSecret / 企业编码 / 接口用户编码 / 待办接口路径 |
| 企业微信 | CorpID / 应用 Secret / AgentId |

每张卡右上角有「已配置 / 未配置」徽标，改完点该卡片的 `保存`，**下一次同步即生效，不用重启**。
想验证：控制台 → `钉钉免登自检`（钉钉链路逐项体检），或设置页「钉钉连接」卡 → `测试连接`。

### 5.3 AI 大模型接口 → 两个层级

| 层级 | 位置 | 说明 |
|---|---|---|
| 个人（推荐先试） | **AI 助手页（#/ai）底部「我的 AI 模型」** | 填 接口地址 / 模型名 / API Key → `测试连通` → `保存我的配置`；网页对话与钉钉机器人立即用你的模型，Key 只存本人账号下，可 `清除我的配置` |
| 全局（全公司共用一个） | `config` 表 `ai:global` | `{"base":"https://api.deepseek.com/v1","key":"sk-xxx","model":"deepseek-chat"}`，见 [config.md](config.md) |
| 全局（老路径，不推荐） | 应用接入页加一条 `应用标识=ai` 或 `应用类型=AI 接口` 的记录 | 接口地址 = Base URL，应用ID = 模型名，应用密钥 = Key |

> ⚠️ **不要把 Key 填在「应用接入」页**：应用接入是公共表，会随页面下发给每个登录用户。
> 生产环境请用「我的 AI 模型」或 `ai:global`。

优先级：**个人配置 → `ai:global` → 应用接入记录 → 都没有则用内置指令引擎**
（仍能建任务、查安排、查审批、找资料，只是不能自由问答）。

### 5.4 运行参数 → `.env` / 环境变量

| 变量 | 作用 | 改了怎么生效 |
|---|---|---|
| `WB_HOST_PORT` | 宿主机端口（默认 8787） | `docker compose up -d` |
| `WB_ADMIN_PASS` | 首次启动写入数据库的管理员密码 | **只在首次初始化有效**；之后用控制台「修改密码」 |
| `WB_DB` | SQLite 路径（默认 `./data/workbench.db`） | 重启容器 |
| `WB_SEED=1` | 首次启动导入演示数据 | 重启容器 |

### 5.5 别找错地方

| 想改 | 结论 |
|---|---|
| 钉钉 AppSecret | ✅ 只在网页里填，存服务端 SQLite；❌ 代码里没有，❌ 前端 JS 里也拿不到 |
| 数据库连接串 | ❌ 没有。本项目用 SQLite 单文件，不是 MySQL/PG |
| 监听端口 | ✅ `.env` / compose；❌ 不要在 `app.py` 里改 |
| 表名 / 数据分组 | ✅ `db.py` 的 `TABLES`（默认 `task/sched/wait/files/ding/meet/cat/apps`），前端只用这套语义名 |
| 钉钉接口基址 | ✅ 仅内网代理场景改 `dingtalk.py` 顶部 `OAPI` / `NEWAPI` |
