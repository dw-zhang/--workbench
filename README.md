# 工作台 · Workbench

**把散在钉钉、飞书、GitHub、金蝶里的待办、审批、日程、文档、群消息，收进一个按人隔离的网页；
再让 AI 在上面干活——判断审批、写周报、建任务、发通知。**

纯 Python 标准库，无第三方依赖，单容器启动，数据落一个 SQLite 文件。

```bash
git clone https://github.com/dw-zhang/dingtalk-workbench.git && cd dingtalk-workbench
./install.sh          # 自动建 .env、构建镜像、启动、打印访问地址与管理员密码
```

---

## 一、它到底解决什么问题

IT / 管理者每天的时间被切成碎片，原因是**信息分散在五个地方，而大脑只能同时记住三件**：

| 以前的动作 | 现在 |
|---|---|
| 早上翻钉钉待办、OA 审批、群消息、邮箱，凭记忆拼今天要做什么 | 首页一屏：今天日程、待办、待回复、会议、待我审批 |
| 群里 @我 的话被刷走，事后被追问「你怎么没回」 | 自动进「等待回复」，可标记已回复，新的直接推钉钉工作通知 |
| 要写周报，回想一周干了啥、翻审批单数 | AI 聚合任务/审批/日程/消息统计，直接出稿 |
| 找三个月前那份文件/那个谁说过什么 | 关键词检索，按本人钉钉权限过滤，点开原文 |
| 审批单堆着，每张都要读正文、回忆制度、查历史 | 每条审批可点「AI 判断」，给出建议 + 依据 + 风险 + 意见草稿 |
| 不同平台各登一次，员工只看得到自己那一摊 | 多平台汇聚入库，员工登录后只看自己的数据 |

一句话：**把人的注意力从「找信息」挪到「做判断」。**

## 三、两个界面：管理员 / 员工

同一套页面、同一个端口，**不是两个系统**。差别只有三件事：从哪登录、侧边栏露出多少、看到谁的数据。

```
                    http://SERVER_IP:8787
                              │
                ┌─────────────┴──────────────┐
                │   登录卡：用钉钉身份进入 │ 管理员 │
                └───────┬────────────┬───────┘
       钉钉内自动免登/扫码 │            │ 管理员密码（.env 的 WB_ADMIN_PASS）
                ┌───────▼──────┐  ┌──▼──────────────┐
                │  员工界面     │  │  管理员界面      │
                │ 只看自己的数据 │  │ 全量数据 + 控制台 │
                │ 无任何配置入口 │  │ 人员/凭证/自检    │
                └──────────────┘  └─────────────────┘
```

| | 员工界面 | 管理员界面 |
|---|---|---|
| 进入方式 | 钉钉工作台点开（免登）/ 浏览器扫码 | 登录卡「管理员」tab + 密码 |
| 顶栏身份 | `👤 姓名` | `🛡 姓名`（点它 = 管理员控制台） |
| 数据范围 | 只有自己的（服务端按 `person_id` 强制过滤） | 全量，可 `?person=<id>` 指定某人 |
| 侧边栏 | 首页 / 任务 / 看板 / 日程 / 日历 / 会议 / 等待回复 / 资料 / AI 助手 | 多出 分类 / 设置 / 应用接入 |
| 右下角 | 无 | 同步状态卡（立即同步 · 连接设置） |
| 管理员控制台 | 看不到 | 人员管理 / 平台配置 / 钉钉免登自检 / 修改密码 |

- 员工点顶栏胶囊只会看到「当前身份 + 退出登录」；直接手输 `#/settings`、`#/apps`、`#/categories` 会被弹回首页。
- 员工刚登录没数据时，页面顶部会出现黄色提示条，直接说原因（没绑账号 / 没开审批权限 / 没拉通讯录），而不是空白页。
- 完整界面图解、字段级填写位置见 **[docs/ui.md](docs/ui.md)**。

## 四、AI 能力（这块是重点）

### 4.1 对话助手：17 个工具，能查也能做

不是"聊天框"，是**会调用系统接口的执行体**。说一句话，它选工具、取真实数据、再回答或执行：

| 类别 | 工具 |
|---|---|
| 查 | `query_approvals` 审批 · `query_todo` 待办 · `query_wait` 等待回复 · `query_schedule` 日程 · `query_files` 资料 · `overview` 总览 · `msg_stats` 群消息统计 |
| 做 | `create_task` 建任务 · `create_schedule` 建日程（回写钉钉日历）· `complete_task` 完成任务 · `submit_approval` 发起钉钉审批 · `send_dingtalk_msg` 发钉钉通知 · `send_email` 发邮件 |
| 产 | `work_report` 周报/日报/月报聚合 · `web_search` 联网搜索 · `fetch_url` 读网页正文 · `get_weather` 天气 |

典型用法：
- 「今天有什么安排」→ 聚合日程 + 未完成任务 + 待我审批
- 「新建任务 核对报价单 高优先级 明天」→ 直接写入任务表
- 「这周我干了什么，写份周报」→ 取真实统计后成稿，不是套模板编
- 「给张三发个钉钉，提醒他今天的单子还没处理」→ 调工作通知接口

> 有副作用的动作（发消息、发邮件、提交审批）会先跟你确认对象和内容，再执行。

### 4.2 审批判断 Agent：读正文 → 比历史 → 下结论

钉钉审批详情接口本来就返回完整表单（事由、金额、附件、谁批过、同意还是拒绝），
本系统把这份正文和流转记录一起入库，再让模型基于**事实**判断，而不是只看标题。

一条实际输出长这样（人名与项目已脱敏）：

```
补卡申请 · 张三 · 待审批
建议：通过（置信度中高）
依据
 - 理由写明具体项目与时段：15日20:40–16日7:53 配合 M-102 客户项目改线、整线、调试，与缺卡时段吻合
 - 已上传缺卡当天考勤截图 1 张
 - 本月补卡第 1 次，制度上限 3 次/月，未触线
风险
 - 跨夜 11 小时不属于正常班次；若期间无加班单，按制度应走「加班申请」而非「补卡」
建议意见：同意。后续跨夜调试请同步提交加班单。
```

四条硬边界（写死在代码里，改不动）：
1. **不自动批**——只出建议和意见草稿，提交动作永远由人点。
2. **无依据不下结论**——没正文 → `need_info`；无制度也无历史 → `manual`，不瞎猜。
3. **金额 ≥ 5000 强制降置信度**并提示复核。
4. **结论只有四种**：通过 / 退回 / 需补材料 / 建议人工，不会冒出第五种。

判断口径：**制度 + 历史双轨**。制度文本从 `ai:policy` 读（管理员可写入），历史取近 90 天同类型已结论单据（最多 12 条样本）；两者冲突时在面板上显式标出「制度说不行，但你上次批了」。

反馈闭环：面板底部「判断对 / 判断有误」写入 `judge_log`，`/api/judge/stats` 算一致率。**一致率过 80% 再谈自动批**，这是准入门槛，不是宣传语。

### 4.3 钉钉机器人

在钉钉群里 @机器人 说话，消息落到「等待回复」，机器人不刷屏。配合定时同步，形成「群里说了 → 工作台留痕 → 该回的人收到通知」的闭环。

详细说明见 [docs/ai.md](docs/ai.md)。

## 五、安装部署（三种，任选）

### 方式 A：一键脚本（推荐）

```bash
git clone https://github.com/dw-zhang/dingtalk-workbench.git
cd dingtalk-workbench
./install.sh                 # 默认 8787 端口
./install.sh --port 9000     # 换端口
./install.sh --seed          # 顺便导入演示数据，先看效果
./install.sh --uninstall     # 停止并删容器（./data 保留）
```

脚本会：检查/安装 Docker → 生成 `.env`（随机管理员密码）→ 构建镜像 → 启动 → 等健康检查 → 打印访问地址和密码。

### 方式 B：docker compose

```bash
cp .env.example .env         # 改掉 WB_ADMIN_PASS
docker compose up -d --build
docker compose ps            # 看到 healthy 即可
```

### 方式 C：不用 Docker（本地跑）

```bash
WB_ADMIN_PASS=test123 python3 app.py     # http://127.0.0.1:8787
WB_PORT=9000 WB_SEED=1 python3 app.py    # 换端口 + 演示数据
```

要求：Python 3.9+，无需 pip install（纯标准库）。

### 首次配置四步

1. 浏览器打开 `http://服务器IP:8787` → 登录卡切到 **「管理员」** tab → 输 `.env` 里的 `WB_ADMIN_PASS`
2. 顶栏出现 `🛡 名字` → 点开 **管理员控制台** → **平台配置** → 钉钉卡片填 `AppKey / AppSecret / CorpId / AgentId` → **保存**
3. 想验证是否填对：控制台 → **钉钉免登自检**（逐项告诉你缺哪个权限、点哪申请）；或设置页「钉钉连接」卡 → **测试连接**
4. 控制台 → **人员管理** → 拉取钉钉通讯录 → 「重新自动匹配」（手机号/邮箱任一命中即绑定，冲突人工裁决）
5. 回首页 → 右下角同步卡点 **立即同步** → 数据进来

完整步骤、反向代理、HTTPS、升级、备份、迁移、排错见 **[docs/install.md](docs/install.md)**；
界面差别与字段级填写位置见 **[docs/ui.md](docs/ui.md)**。

## 六、需要开通哪些权限

**最小可用集**（钉钉，缺一个就有一块功能不通）：

| 权限（开放平台 → 权限管理 里的名字） | 代码/权限点 | 不通的后果 |
|---|---|---|
| 通讯录部门信息读权限 | — | 拉不到部门树 |
| 通讯录部门成员读权限 | — | 拉不到人员，全员无法免登 |
| OA 审批读权限 | `qyapi_work_record` | **一条审批都同步不进来**（唯一的硬阻塞） |
| 钉钉待办读权限（可选） | `Todo.Todo.Read` | 待办不同步；只用审批可忽略 |
| 知识库读权限（可选） | `Document.Workspace.Read` + `Document.Node.Read` | 知识库正文不进资料库 |
| 钉盘/文档（可选） | `Drive.Space.Read`、`Storage.File.Read` | 钉盘文件不同步 |
| 审批高级接口（可选） | `Premium.Workflow.ReadWrite.All` | 「我发起/抄送我」需额外模板编码 |

另外必须配：**应用首页地址**、**登录与分享 → 回调地址**（扫码登录用）、**机器人 → 消息接收地址**（`http://你的地址:8787/dingtalk/robot`）。

飞书 / GitHub / GitLab / Gitea / 禅道 / 金蝶 / 用友的权限点、申请入口、实测报错对照，见
**[docs/permissions.md](docs/permissions.md)**。

## 七、API 与凭证在哪里改

**一句话：业务凭证全在网页里改，代码里没有密钥。**

| 改什么 | 在哪改 |
|---|---|
| 钉钉凭证（AppKey/AppSecret/CorpId/AgentId + 通知开关） | 🛡 管理员控制台 → **平台配置** → 钉钉卡片（保存即生效，不用重启） |
| 同上，只改 4 个基础字段 | 设置页（#/settings）底部「钉钉连接」卡：保存配置 / 测试连接 / 立即同步 |
| 飞书 / GitHub / GitLab / Gitea / 禅道 / 金蝶 / 用友 / 企微 凭证 | 管理员控制台 → **平台配置** → 对应卡片 |
| 钉钉审批判断的"制度"文本 | `POST /api/judge/policy`（管理员），或直接写 `config` 表的 `ai:policy` |
| AI 大模型接口（地址/Key/模型名） | 每人：**AI 助手页底部「我的 AI 模型」**（员工也能改）；全局：写 `config` 表 `ai:global` |
| 监听端口 / 管理员密码 / 演示数据 | 仓库根目录 `.env`（见 `.env.example`） |
| 钉钉接口基址（极少数内网代理场景） | `dingtalk.py` 顶部 `OAPI` / `NEWAPI` 两个常量 |
| 数据文件位置 | 环境变量 `WB_DB`（默认 `./data/workbench.db`） |

凭证存储：SQLite `config` 表，键位形如 `dingtalk:app_secret`；接口只回显"已配置"，Secret 永不回传前端。
各键位完整清单与 curl 示例见 **[docs/config.md](docs/config.md)**。

## 八、数据模型与隔离

```
records(id, database, data JSON, seq, source, updated_at, person_id)   所有平台的数据都归一到这里
schemas(database, title, properties)                                 8 张表的字段定义
persons(person_id, name, status, match_by, phones, emails, ...)       人
accounts(person_id, platform, account_id, name, extra)                平台账号 → 人
config(k, v)                                                         凭证与开关
judge_log(id, pid, verdict, payload, adopted, ...)                    AI 判断与是否被采纳
sessions(token, kind, person_id, expires)                             登录态
sync_log(at, kind, ok, rows, msg)                                     同步记录
```

`database` 就是表名（`task/sched/wait/files/ding/meet/cat/apps`），定义在 `db.py` 的 `TABLES`。

- 每条记录都带 `person_id`，**服务端强制过滤**（`db.PUBLIC_TABLES` 之外的表全部按人过滤），绕过页面直接调 API 也拿不到别人的数据。
- 资料库、会议都按本人钉钉权限隔离：同步时用本人身份枚举，没权限的不入库。
- 公共表只有分类、应用接入。
- 管理员可用 `?person=` 查看指定人（`?person=__nobody__` 返回 0 条，是隔离生效的反证手段）。

## 十、常见问题

| 现象 | 原因与处理 |
|---|---|
| `不合法的appKey或appSecret` | 凭证填错，或应用未发布版本 |
| `appkey permission denied` / 403 | 权限没申请或没生效；控制台「钉钉免登自检」会指出缺哪一项 |
| `ip out of range` | 钉钉后台「服务器出口IP」没加服务器公网 IP |
| 员工打开空白 / 提示不在钉钉环境 | 页面必须从钉钉客户端/工作台进入才能免登；浏览器请用扫码登录 |
| 员工说「看不到同步按钮」 | 正常：同步条只有管理员可见（见 [docs/ui.md](docs/ui.md)） |
| 一条审批都没有 | 缺 `qyapi_work_record`，这是唯一硬阻塞 |
| 改了 `.env` 的管理员密码不生效 | 密码首次启动已写入数据库，用控制台「修改密码」 |
| 同步慢 | 默认按人逐个拉取；先只绑定需要的人，或在平台配置里调小 `cc_per_run` |

更多排错见 [docs/install.md#排错](docs/install.md)。
